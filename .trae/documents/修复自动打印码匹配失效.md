# 修复自动打印套装/多码/清货条码匹配失效问题

## 根因分析

`loadDetail` 中 `loadProductCodes` 使用 `void` fire-and-forget：

```typescript
void loadProductCodes(payload, 1, false);  // 不等待，后台加载
return payload;  // 立即返回，codesIncluded: false，setCodes/multiCodes 为空数组
```

`handleLookup` 拿到 `nextDetail` 后立即调用 `smartAutoPrint`，此时 `nextDetail.setCodes` 还是空数组（码还没加载完），`smartAutoPrint` 里的 `setMatch` 匹配永远不命中，最终走兜底 `sendProductLabel(targetDetail)` 打印主条码。

## 修复方案

**核心思路**：`loadDetail` 返回的 detail 必须包含已加载的码数据，确保 `smartAutoPrint` 能正确匹配。

### 步骤 1：让 `loadProductCodes` 返回更新后的 detail

**文件**: `app/(tabs)/product-query.tsx` 中的 `loadProductCodes`

目前函数最后是 `return;`（void）。修改为在成功路径上返回合并了码数据的新 detail 对象。利用已有的页数据直接构建，不走 `setDetail` 的 functional updater（因为那是基于 stale closure）：

- 套装路径：返回 `{ ...sourceDetail, setCodes: page.items, setCodeCount: page.totalCount, codesIncluded: true }`
- 多码路径：返回 `{ ...sourceDetail, multiCodes: page.items, multiCodeCount: page.totalCount, codesIncluded: true }`
- 失败路径：仍可返回 `undefined`

### 步骤 2：让 `loadDetail` 等待码加载完成

**文件**: `app/(tabs)/product-query.tsx` 中的 `loadDetail`

将：
```typescript
void loadProductCodes(payload, 1, false);
return payload;
```
改为：
```typescript
const detailWithCodes = await loadProductCodes(payload, 1, false);
return detailWithCodes ?? payload;
```

这样 `loadDetail` 返回的 detail 已包含 setCodes/multiCodes，`smartAutoPrint` 就能正确匹配。

### 步骤 3：继续使用 `setDetail` 更新 UI 状态（已有）

`loadProductCodes` 内部仍调用 `setDetail(applyPage)` 确保 UI 状态同步更新，额外返回新 detail 供调用方使用。
