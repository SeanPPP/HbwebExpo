# 修复套装/多码商品 App 显示问题（第二轮）

## 问题现状

```
fast-detail response {
  productType: 1,        ← Product.ProductType = 1
  setCodeCount: 0,       ← SQL 按 SetType=1 统计，返回 0
  multiCodeCount: 10,    ← SQL 按 SetType=2 统计，返回 10
}
```

## 根因

当前后端 SQL 和 API 使用 `ProductSetCode.SetType` 来区分和过滤套装/多码，但 `SetType` 值与 `Product.ProductType` 不一致，导致：
- fast-detail 返回的 count 字段错位（多码数量写到了 multiCodeCount，但 productType 是 1）
- codes API 按 SetType 过滤，type=1 查不到 SetType=2 的记录

## 修复思路

**忽略 `ProductSetCode.SetType`**，以 `Product.ProductType` 作为唯一判断依据：
- `ProductType=1` → 所有子条码都视为套装，统一计入 SetCodeCount，通过套装 API 返回
- `ProductType=2` → 所有子条码都视为多码，统一计入 MultiCodeCount，通过多码 API 返回

## 修改点

### 修改 1：后端 - fast-detail SQL 按 ProductType 统计

**文件**: `/Users/sean/DEV/HBBblazorweb-master-vite/BlazorApp.Api/Services/React/StoreProductMaintenanceReactService.cs`

**位置**: `QueryFastDetailBaseAsync` 方法的 SQL，第 1431-1438 行

当前 SQL 按 SetType 分开统计：
```sql
OUTER APPLY (
    SELECT
        SUM(CASE WHEN psc.SetType = 1 THEN 1 ELSE 0 END) AS SetCodeCount,
        SUM(CASE WHEN psc.SetType = 2 THEN 1 ELSE 0 END) AS MultiCodeCount
    FROM [ProductSetCode] psc
    WHERE psc.ProductCode = p.ProductCode
        AND ISNULL(psc.IsDeleted, 0) = 0
) codeCounts
```

修改为：统计总数，然后在 C# 层根据 `ProductType` 分配到正确字段：
```sql
OUTER APPLY (
    SELECT COUNT(1) AS TotalSetCodeCount
    FROM [ProductSetCode] psc
    WHERE psc.ProductCode = p.ProductCode
        AND ISNULL(psc.IsDeleted, 0) = 0
) codeCounts
```

同时在 `FastDetailBaseRow` 和 `GetFastDetailAsync` 响应构建处也做对应修改，将总数按 ProductType 分配到 SetCodeCount 或 MultiCodeCount。

### 修改 2：后端 - codes API 去掉 SetType 过滤

**文件**: `/Users/sean/DEV/HBBblazorweb-master-vite/BlazorApp.Api/Services/React/StoreProductMaintenanceReactService.cs`

**位置**: 
- `QueryProductCodesPageAsync`（第 1192 行，套装分页查询，传 `setType: 1`）
- `QueryMultiCodePageAsync`（第 1256 行，多码分页查询，传 `setType: 2`）

两处都去掉 `setType` 参数，改为查询该商品的所有子条码（不按 SetType 过滤）。

具体改动：
- `BuildProductSetCodeQuery` 调用时传 `null` 替代 `1` 或 `2`
- 或直接去掉 `setType` 参数，始终查全部

### 修改 3：前端 - 回退之前过度复杂的渲染/加载条件（可选简化）

由于后端现在保证返回的 count 与 productType 一致，前端可以回退到简洁的 `productType` 判断。但保留 count > 0 的兜底也没坏处，可保留现有逻辑不额外修改。

## 实施步骤

1. 修改 `FastDetailBaseRow` 内部类：`SetCodeCount` + `MultiCodeCount` 合并为 `TotalSetCodeCount`
2. 修改 `QueryFastDetailBaseAsync` SQL：去掉 SetType 区分，只统计总数
3. 修改 `GetFastDetailAsync` 响应构建：根据 ProductType 将总数赋给 SetCodeCount 或 MultiCodeCount
4. 修改 `GetSetCodesAsync`：去掉 SetType 过滤
5. 修改 `GetMultiCodesAsync`：去掉 SetType 过滤
6. 验证后端编译
