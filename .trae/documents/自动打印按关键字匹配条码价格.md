# 自动打印按关键字匹配对应的条码和价格

## 背景
自动打印（continuousPrintEnabled）开启时，扫码查询商品后自动触发打印。当前 `smartAutoPrint` 函数已实现了按关键字匹配条码和价格的逻辑，但存在一个 bug 和一处遗漏。

## 当前 `smartAutoPrint` 匹配逻辑（已正确实现）
1. 关键字匹配**套装条码** → 打印该套装条码 + 对应零售价
2. 关键字匹配**多码条码** → 打印该多码条码 + 对应零售价（若无则用主条码零售价）
3. 关键字匹配**清货条码** → 打印清货标签
4. 兜底 → 打印普通商品标签

## 发现的问题

### 问题 1：`keyword` 状态滞后
**文件**: `app/(tabs)/product-query.tsx` 第 750 行

```typescript
await smartAutoPrint(keyword, nextDetail);
```

扫码流程：`setKeyword(barcode)` → `handleLookup(barcode, ...)`，`setKeyword` 是异步的，执行到第 750 行时 `keyword` 仍是旧值，导致 `smartAutoPrint` 用错误的条码做匹配，可能永远不会命中套装/多码/清货条码，最终总是走兜底打印普通标签。

**修复**：将 `keyword` 改为 `nextKeyword`（已在 handleLookup 内部计算为正确的关键字）。

### 问题 2：多结果列表确认路径未使用智能匹配
**文件**: `app/(tabs)/product-query.tsx` 第 898 行 `handleConfirmLookup` 中

```typescript
if (autoPrintOnLookupConfirm && !autoPricingResult.labelPrinted) {
  await sendProductLabel(nextDetail);
}
```

当扫码匹配到多个结果时，用户从列表中选择一个商品确认后，直接调用 `sendProductLabel` 打印普通标签，没有像 `smartAutoPrint` 那样按关键字匹配套装/多码/清货条码。

**修复**：改为调用 `smartAutoPrint(keyword.trim(), nextDetail)`（此处 `keyword` 已在 setKeyword 后更新，不存在滞后问题）。

## 实现步骤

### 步骤 1：修复问题 1 — `keyword` 滞后
**文件**: `app/(tabs)/product-query.tsx`

将第 750 行：
```typescript
await smartAutoPrint(keyword, nextDetail);
```
改为：
```typescript
await smartAutoPrint(nextKeyword, nextDetail);
```

### 步骤 2：修复问题 2 — 多结果确认路径智能匹配
**文件**: `app/(tabs)/product-query.tsx` 第 898 行

将：
```typescript
await sendProductLabel(nextDetail);
```
改为：
```typescript
await smartAutoPrint(keyword.trim(), nextDetail);
```
